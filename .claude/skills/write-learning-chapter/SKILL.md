# 日本語で教材を書く

このスキルでは、完成後の単語置換ではなく、最初から日本語で対象を捉えて文章を組み立てる。
作業前に`docs/learning/AGENTS.md`と`docs/learning/writer-persona.md`を読む。

## 1. 文章より先に読者の観察を決める

次の四点を日本語で一行ずつ書いてから本文を起こす。

1. 読者が最初に見る具体物は何か。
2. そこで何と何を区別する必要があるか。
3. 区別できないと、どの判断を誤るか。
4. 読了後に、読者は何を自分で確かめられるか。

英語の概念名を見出しにして肉付けしない。
実際の値、画面、入力、保存行、失敗、判断場面から始め、関係が見えた後で名前を付ける。

## 2. 用語を訳すのではなく、対象を日本語で言い直す

実装や論文で英語の語を見つけたら、その語を保持したまま日本語の助詞を足さない。
いったん原語を脇へ置き、次を日本語で答える。

- 何を測る、分ける、保存する、または判断するものか。
- 何を分母、条件、比較対象にするか。
- 似た量と何が違うか。
- 日本語の専門分野で定着した名称は何か。

たとえば、`nominal coverage`と`empirical coverage`を先に置いて訳語を当てるのではなく、
「設定した被覆率」と「未使用データで実際に区間へ入った割合」を先に書く。
そのうえで「目標被覆率」「経験被覆率」と名付ける。

## 3. 段落を日本語だけで下書きする

最初の下書きでは、コード識別子、画面上の正確な表示、固有名、文献原題以外の英語を書かない。
日本語名が決まらない箇所は英語で仮置きせず、`［何を表す量か要確認］`のように未解決の問いを残す。

一段落には一つの論点を置き、次の順で書く。

1. 対象または観察
2. その関係
3. 判断への意味
4. 必要なら実装上の根拠

英語を消したときに説明が成立しない段落は、コード名に説明を依存している。
単語を訳すのではなく、段落を組み直す。

## 4. 必要な原語だけを後から戻す

英語を戻せるのは次の場合に限る。

- コード識別子、APIフィールド、ファイルパス
- 製品名、ライブラリ名、規格名
- 画面上の正確な表示
- 文献の原題
- 文献検索や分野間の対応に原語が必要な用語の初出

識別子と正確な表示はバッククォートで囲む。
原語が検索に役立つ場合は、初出だけ「日本語（英語）」とし、その後は日本語を使う。
日本語と英語を毎回併記しない。

## 5. ルー大柴化を段落単位で直す

次のような混在を見つけたら、英単語だけを置換せず、問いと関係を含む文へ直す。

| 避ける書き方 | 書き直す方向 |
|---|---|
| nominal coverageとempirical coverageを比較する | 目標被覆率と、未使用データで確かめた経験被覆率を比較する |
| model uncertaintyとinput variationを分ける | 固定入力に対する予測の不確かさと、入力ばらつきによる点予測の変動を分ける |
| Robustness activityを実行する | 入力ばらつきに対する頑健性を評価する |
| target-specific cohortを作る | 予測対象ごとに評価集団を分ける |
| quantileを返す | 予測分布の分位点を返す |

英語をカタカナへ移しただけで意味が明瞭にならない場合も、同じ問題として扱う。

## 6. 仕上げは読み手として行う

変更した行だけでなく、段落の前後と章全体の読み順を通して読む。
次を順に確認する。

1. 日本語だけを読んで、対象と違いを想像できるか。
2. 英語が専門性の演出や短縮のために混ざっていないか。
3. コード上の名前と一般概念を同じ語として扱っていないか。
4. 日本語化によって、実装上の意味を広げたり狭めたりしていないか。
5. 定義、例、演習、解答で同じ日本語を使っているか。

最後に`node docs/learning/check-japanese-prose.mjs`を実行する。
この検査は既知の逆戻りを見つける安全網であり、文章の質を承認するものではない。
