# Material Decision Workbench デザインシステム

この文書は、画面間で共有する視覚規則、レイアウト、操作、表の表示規則を定めます。
実装上の入口は `apps/web/src/styles.css`、各画面の規則は `apps/web/src/features/*/*.css` です。

## 視覚トークン

| 用途 | 値 | 適用 |
|---|---|---|
| アプリ背景 | `#F5F7FA` | ページ背景 |
| 面 | `#FFFFFF` | 作業面、パネル、入力 |
| ヘッダー | `#0F1B2D`から`#09243E` | 最上部のナビゲーション |
| 本文 | `#18202C` | 見出し、本文、入力値 |
| 補助文字 | `#5D6775`から`#718096` | 単位、説明、補助情報 |
| 主要色 | `#1F5FC4` | 主要操作、選択、フォーカス |
| 境界線 | `#D8E0EA` | パネル、表、区切り |
| 成功 | `#147255` | 保存済み、目標内、利用可能 |
| 注意 | `#91550D` | 学習範囲外、表示範囲外、要確認 |
| エラー | `#B42318` | 入力エラー、競合、取得失敗 |

書体は `Noto Sans JP`、`Yu Gothic UI`、`Meiryo`、システムフォントの順に使います。
数値には `font-variant-numeric: tabular-nums` を適用します。
本文とデータUIはおおむね12pxから15px、補助ラベルは11px以上、badgeは10px以上、画面見出しは19pxから21pxです。
SVGの軸目盛りなど面積制約が明確な要素だけを例外とし、本文級の情報を9pxから10pxへ縮めません。

角丸は原則3pxから6pxです。
影は固定ヘッダーなど、面の重なりを示す場合だけに使います。
フォーカスは主要色のアウトラインで表示し、色だけに依存させません。

## アプリ全体のレイアウト

画面上部は次の順に積み重なります。

1. 48pxを基準とするアプリヘッダー
2. プロジェクト名、状態、プロジェクト内メニューを持つコンテキストバー
3. 必要な場合だけ表示する状態通知
4. 各画面の作業面

ヘッダーとコンテキストバーはスクロール中も上部に残します。
プロジェクト内メニューは、タスクが対応する画面だけを表示します。
画面固有の主要操作はコンテキストバーか作業面の見出し付近に置き、アプリヘッダーへ増やしません。

候補比較画面は、左の選択候補入力パネルと右の比較面で構成します。
入力パネルの幅はドラッグ、矢印キー、Home、Endで変更でき、ダブルクリックで初期値へ戻します。
幅はローカルストレージへ保存し、820px以下では上下配置に切り替えます。
ページ全体には横スクロールを発生させず、広い表やグラフは専用のviewport内だけを横スクロールさせます。
レイアウトの切替は可能な限り画面幅ではなく、実際に利用できるコンテナ幅を基準にします。

比較面は、判断サマリー、候補比較表、必要な場合の曲線ファミリー、応答曲線と近い過去実績の順に配置します。
判断サマリーは目標設定、モデル支持範囲、予測区間の重なりを独立して示し、最良候補の自動選定や順位付けは行いません。
応答曲線と近い過去実績は1280pxを超える場合に横並びとし、境界のドラッグまたはキーボード操作で比率を変更できます。
1280px以下では縦積みにし、820px以下では複数の応答曲線も一列にします。

## 操作の規則

- 候補、プロジェクト、探索runなど、別の対象へ移る操作はURLを更新し、ブラウザの戻る・進むで復元できるようにします。
- 同じ画面内の選択同期では履歴を増やしません。
- 入力変更時は変更した候補のプレビューだけを更新します。
- 詳細予測、スナップショット保存、候補追加など、結果を残す操作は明示的なボタンで実行します。
- 押せる行とボタンはhover、選択、focus-visibleの各状態を表示します。
- 幅調整用の境界はマウス、タッチ、キーボードで操作できる `separator` として実装します。
- 削除や複製の操作は対象行から行い、操作によって比較面のスクロール位置を不必要に変えません。
- 読込中、古い結果、更新中、失敗を区別して表示し、古い予測を最新値として見せません。
- パネルの表示切替は、XLSX出力や候補追加など結果を残す操作と視覚的に分けます。
- 対応していない機能は空の半面パネルとして残さず、利用できる証拠パネルへ幅を譲ります。
- 判断履歴は比較や類似実測を覆う固定面にせず、作業の流れの中へ開閉可能な面として置きます。

## 表の規則

- 列見出しは中央揃え、行見出し、識別子、文字列は左揃えにします。
- 数値セルと数値入力は右揃えにし、等幅数字を使います。
- 同じ変数は行間で小数点以下の桁数を揃えます。
- 予測特性の表示順は `TaskDefinition.outputs` の配列順を正本とし、API辞書やモデルPackage内の格納順には依存しません。
- 既定の表示桁数には `TaskDefinition.display_decimals` を使います。
- プロジェクト固有の `display_decimals` は表示だけを上書きし、保存値や計算値を丸めません。
- 単位は `TaskDefinition.outputs[].unit` を正本とし、次元なしの `1` は表示しません。異なる単位が混在するグループ見出しへ、先頭項目の単位を流用しません。
- 編集中は入力しやすい表記を優先し、未編集中は末尾のゼロを含む規定桁数で表示できます。
- 候補比較表では候補名を左側、行操作を右側に固定し、入力と予測の列を横スクロールできます。
- 表見出しは縦スクロール中も残し、選択行は主要色の背景と左端の印で示します。
- 予測値、実測値、不確かさ、目標への適合、学習範囲への適合を同じ意味の値として扱いません。
- 単位と不確かさの意味は値の近くへ表示し、注意状態は色に加えて文言または印でも示します。
- 類似実測は特性ごとに比較できる列へ分け、候補化できないデータに空の操作列を出しません。
- 横スクロールする証拠表の行操作はデータ列へ重ならない幅を確保し、途中の列へ固定しません。

## 文字と用語の規則

- overlineの短い英語は画面分類として使えますが、ナビゲーション、操作、表見出しは日本語を主にします。
- Dataset、Profile、Runtimeなど開発者が判断に使う概念は、初出で日本語と英語を併記し、その後は日本語を使います。
- 内部ID、digest、manifestなどは主要ラベルにせず、必要な識別情報として技術詳細へ置きます。
- 日本語の補足には全角括弧を使い、長い補足は見出し本文と別要素にして語の途中で折り返さないようにします。
- 元データ由来の内部事情や学習対象の除外条件は、入力グループ名へ埋め込まず注意説明へ分離します。

## グラフの規則

- 候補ごとの線や点は、凡例と選択状態を対応させます。
- 軸名、単位、表示範囲を明示し、表示範囲外の値は切り落とした事実を表示します。
- 応答曲線は予測の傾向と不確かさを示し、観測値と混同させません。
- 応答曲線の既定Y軸は曲線の変化へ合わせます。業務上の基準範囲と保存済み範囲は明示的に切り替えます。
- 現在値が曲線の計算範囲外にある場合は曲線へ接続せず、計算端点と現在値の関係を文言で示します。
- 曲線ファミリーは、固定した条件と変化させた条件を画面上で判別できるようにします。
- SVG上の値はhoverだけに依存せず、キーボードフォーカスでも確認できる当たり領域を持たせます。
