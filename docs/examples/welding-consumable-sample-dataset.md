# 多段構造の検証用合成データ（溶接材料）

`data/source/welding_consumable_multistage_synthetic_dataset.xlsx` は、原料配合から特性までが多段になる問題を模した合成データです。
実測値ではありません。[多段Chainアーキテクチャ](../decisions/multistage-chain-architecture.md) の方針を、契約や画面を作る前に具体的な行と列で確認するために使います。

Stage Cの観測familyを組み立てるDataset Profile契約には接続済みです。
Stage Bは実測溶着金属成分300観測を正本とする単独Task・Packageへ接続済みです。
詳細は [Stage B Task / Package](welding-stage-b-package.md) を参照してください。

## 再生成

```powershell
npm run data:build:welding-sample
```

`--blends`、`--runs`、`--seed`、`--output` を指定できます。既定は乱数seed `20260725`、配合120件、施工300件で、同じseedなら同じ内容を再生成します。

## Stage Cの正規化artifact

```powershell
npm run data:build:welding-stage-c-views
```

元Excelは変更せず、`data/derived/welding-consumable-stage-c/` に次を生成します。
`data/derived/` は再生成物なのでGit管理しません。

- `tensile.jsonl`：引張試験の600観測
- `charpy.jsonl`：シャルピー試験の2,700観測
- `corrosion.jsonl`：腐食試験の103観測
- `summary.json`：family・目的変数ごとの利用行数、施工group数、除外理由

読取規則の正本は
`backend/src/material_workbench/data/observation-profile-welding-consumable-stage-c-v1.json`
です。
各行は試験キー、溶接施工キー、溶接条件キー、溶着金属成分キーをprovenanceとして保持します。
分割groupは試験片ではなく溶接施工キーです。
`relationEx` は結合索引にだけ使い、relationの行を複製しても学習候補行は増えません。

画面では「開発・管理 → Developer Center → 学習View」で、family・目的変数ごとの利用行数、施工group数、除外理由と観測行を確認できます。

## 段の構造

```text
[配合明細（原料 slot × 11〜20点）]
        |  段A: 原料成分行列 + フープ + 充填率（厳密な線形変換）
        v
[材料成分 31成分]  +  [溶接条件（入熱・ガス・電圧・姿勢）]
        |  段B: 歩留まりが入熱・塩基度・酸素に依存する非線形変換
        v
[溶着金属成分 16成分（実測相当。シートに存在する）]
        + [溶接context（入熱・予熱）]
        + [試験context（試験温度）]
        |  段C: 強度・延性・靭性・腐食
        v
[引張・シャルピー・腐食の反復観測]
```

段Aの出力である材料成分はシートに持ちません。`配合明細`、`原料成分`、`フープマスタ`、`配合.充填率[%]` から一意に再現できる派生量だからです。
配合比は表示桁（小数4桁）のまま合計が厳密に100%になるため、ワークブックの値からそのまま線形変換を再現できます。

段Bの出力である溶着金属成分は `溶着金属成分` シートに持ちます。中間量に教師データがあるという、この問題構造の要点を再現するためです。

## 生成式と実装境界

### 段A

材料成分は次の式で生成します。

```text
core_c = Σ(配合比_i × 原料成分_i)
wire_c = 充填率 × core_c + (1 - 充填率) × フープ成分_c
```

フープと充填率を固定すれば、コア内配合比に対してアフィンです。
コア内配合比と充填率を同時に変数にすると積が生じるため、Phase 1のv1ではフープと充填率を固定します。
候補の疎な配合明細はPackage実行直前に絶対ワイヤ質量分率へ変換し、その後の成分行列との積を `deterministic-linear` runtimeで行います。
原料・フープ成分とD50は科学変換master、単価と調達区分は商用catalogとしてrevisionを分けます。
価格変更だけでStage Aの科学Package digestを変えず、粉体配合コストはコア内配合比で原料単価を加重した円/kg-coreのderived decision metricとして計算します。
合成データにはフープ単価がないため、総ワイヤコストは算出しません。

### 段B

段Bが生成式で使う入力は次です。

- 材料成分31項目
- 原料由来の合金粉D50加重平均
- 入熱、電圧、シールドガス、ガス流量、溶接姿勢

電流と溶接速度は入熱の算出に使いますが、段Bの生成式へは入熱として入ります。
出力はC、Si、Mn、P、S、Ni、Cr、Mo、Cu、Ti、B、Nb、V、Al、N、Oの16成分です。

### 段C

段Cは溶着金属成分だけでなく、入熱と予熱を強度・遷移温度の生成へ直接使います。
シャルピーの吸収エネルギーと脆性破面率は、さらに観測行固有の試験温度を使います。

| 観測family | 追加context | 出力 |
|---|---|---|
| 引張 | 入熱、予熱 | 引張強さ、0.2%耐力、破断伸び、絞り |
| シャルピー | 入熱、予熱、試験温度 | 吸収エネルギー、脆性破面率 |
| 腐食 | 試験液 | 腐食速度 |

試験液は腐食速度の意味を定めるcategorical inputとして保持しますが、この合成データの生成式における係数はゼロです。
試験方法（浸漬試験）と浸漬時間（336 h）はfixed semantic context、試験片位置は測定metadataとして保持します。
生成式にない列を数値特徴へ自動昇格しません。
学習用の行は観測family別に構築し、`relationEx` の一行をそのまま全出力の学習行にはしません。

### 逆算

- 使用原料集合、フープ、充填率を固定し、whole-wire絶対質量分率を連続変数として求める場合はLPです。
- 原料採否、群からの選択数、相互排他、フープ選択を同時に求める場合はMILPです。
- 調達可否を単なる許可集合として事前に絞るだけならLPのままです。
- 基準配合からのL1距離はLPですが、L2距離はQPになるためv1では扱いません。

詳しい契約は [多段Chainアーキテクチャ](../decisions/multistage-chain-architecture.md) に記録します。

## シート構成

| シート | 行数の目安 | 役割 |
|---|---|---|
| `原料マスタ` | 252 | 原料の選択肢。グループ、調達区分、単価、粒度D50、形状 |
| `原料成分` | 252 | 原料×31成分の行列。段Aの変換行列そのもの |
| `フープマスタ` | 4 | 外皮の材質と成分。段Aの線形合成に入る |
| `配合` | 120 | 配合の頭。フープ、充填率、ワイヤ径、設計狙い |
| `配合明細` | 約2100 | 疎な `(配合, 原料, 配合比[%])`。1配合あたり11〜20点で合計100% |
| `溶接条件` | 42 | 電流、電圧、速度、入熱、予熱、シールドガス、姿勢 |
| `溶接施工` | 300 | 配合×溶接条件の実施単位 |
| `溶着金属成分` | 300 | 実測相当の中間量。16成分 |
| `引張試験` | 600 | 1施工あたり2本の反復観測 |
| `シャルピー試験` | 2700 | 3温度×3本の反復観測。温度は判断対象の一部 |
| `腐食試験` | 約100 | 一部の施工だけに存在する |
| `relationEx` | 約3400 | エンティティ結合。1行が観測1件で、1行を学習行として直接使わない |

キー列は既存ソースと同じ `＿key**` 形式です。

## 埋め込んだ性質

方針の検証に必要な性質を意図的に入れています。

- **選択肢と実使用の差**：原料は252点あり、調達区分が `廃止予定` の66点は配合に現れません。1配合が使うのは11〜20点です。
- **群による選択構造**：鉄粉、合金鉄、純金属粉、脱酸剤、スラグ形成剤、アーク安定剤、炭素源、ガス発生剤、バインダの9群があり、群ごとに現実的な添加量レンジを持ちます。鉄粉が残部を取ります。
- **設計狙いによる偏り**：`設計狙い`（低温靭性、高強度、耐食、原料代替、標準）が原料の選ばれやすさを変えます。探索や類似度が意味を持つ構造になっています。
- **成分に落ちない原料属性**：合金系原料の粒度D50の加重平均が段Bの歩留まりへ効きます。材料成分ベクトルだけでは説明できない残差として現れます。
- **中間量の非線形性**：Mn・Siの歩留まりは入熱とシールドガスで下がり、Ti・B・Alの歩留まりは酸素に対して指数的に落ちます。酸素はスラグ塩基度とシールドガスで決まります。
- **試験温度が判断対象**：シャルピーは遷移曲線として生成しており、吸収エネルギーと脆性破面率が同じ遷移温度を共有します。
- **観測の反復と欠測**：引張は2本、シャルピーは3温度×3本、腐食試験は約36%の施工にしかありません。目的変数ごとに学習コホートが変わります。

## この合成データで確認できること

- 疎な配合を正本として持ったときの、差分表示・XLSX往復・候補比較の見え方。
- 原料→成分の線形変換を `deterministic-linear` runtimeとして扱えるか。
- 段単体精度（実測溶着成分入力）と通し精度（予測溶着成分入力）の差の出し方。
- 目標成分から配合を求める線形計画が、群制約と調達区分の下で解けるか、解が存在しないことを示せるか。

Stage Aは `models/packages/welding-stage-a-deterministic-v1` に科学masterを固定した
決定論的Packageとして実装済みである。120配合の期待値はPackage内の
`reference/stage-a-golden-120.json` で再現検証する。商用catalogは
`models/catalogs/welding-stage-a-commercial-v2.json` として科学Packageから分離する。
新規候補はactiveなv2を参照し、保存済み候補の再現にはv1/v2双方のimmutable
catalogとDesign Spaceを完全一致refで解決する。
31成分軸は固定契約であり、元Excelの列名・順序が契約と異なる場合は暗黙に読み替えず
Package生成を停止する。active/availableの選択は `models/active-transforms.json`、
実行導線は `GET /api/transforms` と `POST /api/transforms/{transform_id}/execute`
で確認できる。

## この合成データで確認できないこと

- 実際の冶金的な妥当性。歩留まりや遷移温度の係数は説明のために置いた値です。
- 実データにある欠測・異常値・単位揺れの実態。品質診断の検証には別途、崩したソースが必要です。
